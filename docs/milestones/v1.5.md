# Version 1.5 — assets, the Barebones style, mods screen, caves and speed

v1.5 fixes Kenzo's playtest of v1.4 and builds the Barebones style he defined. It puts every asset (font, sound, textures, the downloaded packs) inside the .app. It finds and fixes broken textures, with tools that make checking easy. It adds three built-in styles (Vanilla, Barebones and Realistic) with one Shaders switch, and builds native versions of the trailer-look mods from lowresbones' video "Make Minecraft look like the trailer (UPDATED)". It also adds a clearer Mods screen, caves that keep the surface grass like vanilla, and shader speed on Apple silicon. Same Milestone rules as CLAUDE.md (Step 0, small commits, tests, one PR per milestone, at most one screenshot, except M60 and M61's contact sheets), plus:

- **Faithfulness:** gameplay and world generation still match modern Java (the 1.21.11 data for worldgen). No extra changes gameplay. The Vanilla mode stays M53's look, checked by the reference images. Only M67 changes generation, and only in new chunks.
- **Assets come from downloads, never new art:** vanilla's textures, sounds and font come from assets/vanilla (scripts/fetch-vanilla-assets.sh). The resource packs and mod .jars come from assets/downloads/, which Kenzo fills. All of them are git-ignored and bundled only into Kenzo's own .app. When something is missing, stop and ask Kenzo for it with a link. Don't work around it or draw replacements.
- **Mods from the video are rebuilt natively:** Rustcraft doesn't run Java mods. Each mod is reimplemented from its behavior (its Modrinth page, its configs and assets inside the .jar), never from its code. Each one gets its own toggle in Video Settings → "Extras..."; all of them are client-side. Its sounds or textures, if any, are read from the .jar in assets/downloads/mods/ at runtime. All the client-side ones are on by default in the Barebones and Realistic styles and off in Vanilla, with shaders on or off. Every one can be turned on or off in any style.
- **Kenzo's M4 is the target machine:** every frame-rate and time budget in v1.5 is measured on Kenzo's M4 Mac (the Mac the sessions run on), at 1080p for the gate rows and at the display's native resolution where an entry says so.
- **Kenzo checks textures by eye** with the Texture Viewer (M60). Its marks file is the input for later texture fixes.

Do the same with cargo run. - **One asset root, found the same way everywhere:** the game resolves its read-only asset root once at startup, in this order: --assets <dir> if given; the .app's Contents/Resources (found from the executable's path, never from the current directory); then the repo folder (for cargo run). Writable things (saves/, options.ron, resourcepacks/, mods/, screenshots, logs) stay in the game folder as now. Log the chosen root and each layer it found, once. Never depend on the current directory.
- **Downloads folder:** assets/downloads/ (git-ignored) holds resourcepacks/ (the Barebones packs and Patrix 32x, as .zip or folders) and mods/ (the mod .jars, read as zips). The game lists the packs in assets/downloads/resourcepacks/ as built-in packs: they show in the Resource Packs screen marked "Built in", can be turned off but not deleted, and can be used by the graphics modes (M62). Packs in the user's resourcepacks/ folder still work as before. scripts/check-downloads.sh prints, for each expected pack and mod, found (with the file name and version) or missing (with its Modrinth link), and exits non-zero when one is missing.
- **Fix the lookups:** every texture that vanilla has under another path is fixed in assets/data/texture_names.ron (or the loader), not with new files. - **The bundle script refuses incomplete builds:** scripts/bundle-macos.sh checks before copying that assets/vanilla has textures, models, blockstates, items, lang/en_us.json, sounds.json, every .ogg file sounds.json references (count them), font/default.json and every font page it names. It fails with a clear message ("assets/vanilla is missing N sound files: run scripts/fetch-vanilla-assets.sh") instead of building a silent app. It also runs scripts/check-downloads.sh and warns, but still builds, when packs or jars are missing. It copies the whole vanilla layer, assets/downloads, assets/textures, assets/data and the bundled mods. After building, it runs scripts/check-bundle.sh (new), which counts the files in the .app against the source folders and starts the app's binary from / with --asset-report --exit. It fails if any count differs, any sound event is silent or the font is missing.
- **Never invisible text:** if no layer has a bitmap font (for example, a build without assets/vanilla), draw text with egui's built-in font and log one line saying so.
- **Tests:** the asset root resolves to Contents/Resources when the executable is inside an .app layout (a temp folder), whatever the current directory is; the bundle check passes on a fake complete layer and fails, naming what's missing, on one with no sounds or no font; packs in assets/downloads/resourcepacks/ show as built in; check-downloads.sh matches fake files named like the real downloads; with assets/vanilla present, the asset report has 0 silent sound events and no missing vanilla texture (only listed Rustcraft-only ones).

### - [x] M60 — The texture checker: audit, contact sheets and the Texture Viewer
- **Kenzo's report:** many mob, block and item textures are missing or broken. Either fix them with screenshot analysis or make it quick for Kenzo to check each one. This milestone builds both tools; M61 uses them to fix.
- **Step 0:** print the number of block models, item models and mob models the game draws, and which layer each texture came from (counts per layer). For every mob in mobs.ron, print its texture's path, declared texture size and actual PNG size, and flag every mismatch. List the animated textures (.png.mcmeta) and whether the renderer animates each one. List the tinted textures (grass, foliage, water, redstone, stems, spawn eggs, leather armor, potions) and where each tint comes from.
- **--texture-audit [--mode <mode>]:** renders offscreen, without a window, into labeled contact sheets of up to 256 thumbnails each in target/texture-audit/<mode>/ (git-ignored):
  - every block, as placed in the world (a lit cube or its model), from a fixed 3/4 view and from the top, in a plains biome so tints apply;
  - every item: its inventory icon at 2×, and the held-in-hand view for tools;
  - every mob: front, side and back, idle pose, adult and baby where they exist, and each texture variant;
  - the GUI sprites.

  Each thumbnail has its id underneath and a colored border when a detector flagged it. The audit also writes target/texture-audit/report.json and a short summary.
- **Detectors (each one a function with its own test).** Each flag names the detector, the texture and the model or mob part. They look for:
  - the missing-texture placeholder anywhere in the render;
  - a model or mob part that references a texture no layer has;
  - a face that's fully transparent where the model is opaque;
  - UVs outside the texture;
  - a mob part whose faces sample more than 50% transparent pixels (a sign of a wrong layout);
  - a declared texture size that doesn't match the actual one;
  - an animated strip drawn as one squashed image (the rendered face's aspect differs from one frame's);
  - a tinted texture drawn untinted (gray where a tint is expected), or a tint applied to a texture that has none;
  - an item icon that's empty or a single flat color;
  - block faces whose orientation differs from the blockstate's (log tops, furnace fronts, stairs);
  - a block whose rendered sides are identical to another block's when their textures differ (a sign of a lookup falling through to the wrong texture).
- **Every texture stack:** run the audit for the Vanilla textures, the Barebones pack stack (all four packs) and, once M62 adds it, the Realistic stack, so mobs are checked with and without the CEM models from M58.
- **The Texture Viewer (Kenzo's quick check):** it opens from Options → Video Settings → "Texture Viewer...", from the title screen's Options, with --texture-viewer, or with the command /textures in a world.
  - **Left:** categories (Blocks, Items, Mobs, GUI, Particles, Environment) with a search box.
  - **Middle:** a grid of thumbnails rendered the same way as the audit, with a red corner on anything a detector flagged and a check or cross on anything Kenzo has marked.
  - **Right, for the selected one:** a large 3D view (drag to rotate; mobs play idle, walk and attack animations; blocks can be shown placed next to grass and stone), the raw texture with the model's UV boxes drawn over it, which layer or pack it came from, its detector flags, and a dropdown for the texture set so Kenzo can compare.
  - **Keys:** the arrow keys move through the grid, Enter opens the large view, B marks broken (opens a one-line note box; Enter saves), K marks OK, U clears the mark, F jumps to the next flagged one, Esc closes.
  - **Marks:** they're saved right away to texture-marks.ron in the game folder (id, texture set, mark, note, date), and the top of the viewer shows "N broken, M OK, K unchecked". --texture-marks prints the file as a table. A later session fixes from this file.
- **Speed:** the viewer opens in under 1 s and scrolls at 60 FPS on the M4: render thumbnails once into an atlas in the background and cache them until the packs change.
- **Tests:** each detector catches a fixture made to break it (a placeholder, a squashed strip, an untinted grass, an out-of-range UV, a 64×32 mob texture declared 64×64) and passes a correct one; the marks file round-trips and survives a reload of the packs; --texture-audit finishes for every block, item and mob without a panic; the viewer's keys change the marks.
- **Done when:** the tests pass, the PR lists the audit's flags per detector and per category (with the top 20 by severity), the perf gate passes (the viewer and audit add nothing to normal frames), and one image: the mobs contact sheet with its detector borders.

### - [ ] M63 — Player animations (Not Enough Animations)
- **Step 0:** the mod notes (above). Print the player model's parts and current third-person poses (idle, walk, swim, sneak, attack, use).
- **Player poses (Not Enough Animations):** third-person and other players get vanilla first-person actions as body poses. That means eating and drinking (hand to mouth, head bob), holding a map in one or both hands, climbing ladders and vines (arms and legs alternate), riding (legs to the sides, arms holding the reins of horses or the boat's paddles), bow draw and crossbow load and aim, shield block, spyglass and goat horn, sleeping fixes and the throwing arm for tridents and snowballs. Plus smooth blending between poses and the item in hand following the arm. Shown on every player model, including in LAN. Share: 0.1 ms CPU.
- **Walk animations (Kenzo: "almost every walking animation is broken, the mobs' footsteps are way too big"):** first measure, then fix the shared limb-swing values every walking mob and player uses, the way vanilla's WalkAnimationState does. Each tick, the target speed is min(horizontal distance moved × 4, 1). Speed moves 40% of the way toward it, and position advances by speed. Both are interpolated with the partial tick, and speed is clamped to 0–1. The models use vanilla's formulas, for example legs' xRot = cos(position × 0.6662) × 1.4 × speed (opposite phase for the other leg), arms in humanoids cos(position × 0.6662 + π) × 2 × speed × 0.5, all in radians. Step 0 prints, for a zombie, cow, pig, chicken, spider, villager and player walking at normal speed, the limb position and speed per tick and the peak leg angle, next to vanilla's (about 0.6 rad at a walk). It names the cause. Fresh Animations reads the same values as limb_swing and limb_speed (M58), so the fix must also correct its animations. Check both: with the pack off (vanilla models) and on (its models). Test: peak leg angle within 10% of vanilla's for each of those mobs at walking and sprinting speed, with and without Fresh Animations; standing still, the legs settle to 0 within a second.
- **Tests:** each pose triggers on its action and blends out; the held item follows the arm in every pose; two clients see the same pose on the same player.
- **Done when:** the tests pass, the PR has the Step 0 mod notes and the list of poses built, the perf gate passes with the shares, and one screenshot: a player drawing a bow in third person in Barebones + Shaders.

### - [ ] M64 — Particles and water (Visuality, Cave Dust, Particle Rain, Make Bubbles Pop, Wakes)
- **Step 0:** the mod notes for all five (above). Print the particle system's limits (max particles, per-frame cost at 1,000 and 5,000), and how rain, snow, bubbles and boats are drawn now.
- **Build each one as its notes describe.** In outline:
  - **Visuality:** the small particles it adds (for example, hit particles by mob type, sparkles on shiny blocks and ores, rings in rain) with its defaults.
  - **Cave Dust:** slow floating dust motes in dark, enclosed spaces, by light level and depth.
  - **Particle Rain:** rain and snow as particles instead of (or on top of) the falling strips, with splashes on blocks, ripples on water, and mist and sand dust in heavy rain or deserts. Keep M57's wetness and rain rings in the shader modes, without doubling them.

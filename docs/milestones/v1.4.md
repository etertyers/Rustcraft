# Version 1.4 — the trailer look

v1.4 gives Rustcraft a second look, **Trailer**, styled after the Minecraft trailers and Complementary Reimagined, and makes it the default. The **Vanilla** look stays exactly as it was after M53, and one key (F12) switches between them. Both are built natively in Rustcraft's wgpu renderer; Rustcraft doesn't load OptiFine/Iris shader packs (see Kenzo's decisions in CLAUDE.md). Same Milestone rules as CLAUDE.md (Step 0, small commits, tests, one PR per milestone, at most one screenshot), plus:

- **Faithfulness:** the Vanilla look and all gameplay still match modern Java. The Trailer look is deliberately not vanilla; only how things look changes. It reads the same light levels, fog distances (M51), sky colors and times of day as vanilla, and builds on top of them. Nothing in the Trailer look may change gameplay or what's visible to the player in a way that helps (caves that are dark in vanilla stay dark).
- **The Vanilla look is untouchable:** with Visuals set to Vanilla, the frame is drawn by M53's passes with M53's shaders. A test renders fixed --shot scenes and compares them with reference images rendered at M53 (at least 99.9% of pixels within 1/255 per channel), and the perf gate's Vanilla row must stay within 3% of M53's average FPS.
- **Frame-rate budgets** (Kenzo's Mac mini M1, 1920×1080, render distance 9, vsync off, the --perf-test route):

| Look | Average FPS | 1% low | Extra GPU time per frame |
|---|---|---|---|
| Vanilla | ≥ 97% of M53's | ≥ 40 | none |
| Trailer Low | ≥ 100 | ≥ 50 | ≤ 2.0 ms |
| Trailer Medium (default) | ≥ 75 | ≥ 45 | ≤ 4.5 ms |
| Trailer High | ≥ 60 | ≥ 40 | ≤ 7.5 ms |

- **The three Trailer resource packs** (Bare Bones, Barebones Better Leaves, Fresh Animations) are never bundled or committed; their licenses forbid redistribution. Kenzo puts them in resourcepacks/.

#### Checkpoint K — the trailer look

### - [x] M54 — Render pipeline, the Visuals switch and the GPU profiler
- **Step 0 (measure before changing anything):** list every render pass and pipeline in src/render/mod.rs in draw order (world, translucent, mobs, hand, sky, clouds, crack, outline, UI), the surface format, and where the frame is cleared and presented. Render reference images for the M54 vanilla test now, before any change: --shot scenes forest-noon, lake-sunset, cave-torches, nether-wastes, end-island and underwater-ocean (add them to --shot if missing; seed 12345) into tests/reference/vanilla/ (commit these small PNGs). Run --perf-test and record the baseline. Check whether the adapter has wgpu's TIMESTAMP_QUERY feature on Kenzo's M1 and say so. List resourcepacks/ and, for each of the three Trailer packs, its pack format and every file type the loader skips today.
- **Two looks, one renderer:** `options.visuals` = { look: Vanilla | Trailer (default Trailer for new installs, and for existing installs on first run of v1.4), quality: Low | Medium (default) | High, and a per-effect override for each effect in M55–M57 }. Name the code src/render/visuals/ (src/look.rs already means "everything texture-derived"). Video Settings gets "Visuals: Vanilla/Trailer", "Trailer Quality: Low/Medium/High" and a "Trailer Settings..." screen with each effect's toggle. A new key binding "Toggle Visuals" (Misc, default F12, rebindable) switches looks in game and shows "Visuals: Trailer" or "Visuals: Vanilla" with M50's overlay message. Command line: --visuals vanilla|trailer and --quality low|medium|high, for --shot, --bench and --perf-test.
- **Switching is instant:** both looks' pipelines are created at startup (compiling Trailer's shaders must add less than 300 ms to startup; measure it), so F12 never stalls for more than one frame, except when the two looks use different resource packs (below), where the old textures stay on screen until the new ones are ready on a background thread.
- **Each look keeps its own resource packs:** the Resource Packs screen edits the list for the look that's on. Vanilla's list starts empty. Trailer's list starts as Kenzo's current list with the three Trailer packs added on top if they're in resourcepacks/ (order, top first: Fresh Animations, Barebones Better Leaves, Bare Bones, then the rest), matched by the pack's name in pack.mcmeta or its file name, ignoring case, spaces, dashes and version numbers. If any is missing, the Trailer list just leaves it out and the log says which. Add a test with fake packs named like the real downloads.
- **The Trailer pipeline (scaffold only in M54, effects in M55–M57):** the Trailer look renders the world into an HDR target (Rgba16Float) with depth, then runs post passes into the surface. The UI is drawn after, untouched, in both looks. In M54 Trailer's only post pass copies HDR to the screen with vanilla's colors, so Trailer looks like Vanilla until M55. Mobs, the hand, held items, particles, the dragon, the sky and clouds all draw into the HDR target in Trailer.
- **What the shaders need to know about each face:** add one u32 attribute to the vertex: the face normal (octahedral, 16 bits), a material class (8 bits) and flags (8 bits). Material classes come from a new assets/data/materials.ron (block or tag → class), never from match arms: opaque, cutout_leaves, cutout_plant (grass, flowers, ferns, saplings), crops, vines and hanging plants, water, lava, ice, glass and stained glass, emissive (with a strength: glowstone, sea lanterns, lava, fire, torches, lanterns, froglights, shroomlights, jack o'lanterns, end rods, redstone lamps when lit), and metal-ish blocks that shine a little (gold, iron, copper, diamond, emerald, netherite blocks). The Vanilla look's shaders ignore the new attribute. Measure the chunk mesh memory increase and note it in the PR.
- **GPU profiler:** with TIMESTAMP_QUERY, write timestamps at the start and end of each pass (Apple GPUs can't time inside a pass, so give each effect its own pass) and read them back two frames later without stalling. Without it, fall back to measuring each effect by turning it off and comparing --bench frame times, and say which method was used. F3 shows the per-pass times (ms, averaged over 60 frames) in Trailer. --perf-test writes them to docs/perf/m<N>.md, and --perf-test --all-looks runs Vanilla and Trailer Low/Medium/High in one go.
- **Each effect's share of Trailer Medium's 4.5 ms** (enforced from the milestone that adds it): shadow maps 1.4 ms, extra world shading (sun, shadows lookup, leaves) 0.6, water (reflections, refraction) 0.8, light shafts 0.5, bloom 0.4, sky and clouds 0.3, tone mapping, FXAA and the rest of the post chain 0.3, swaying plants and wetness 0.2. Low and High get their own settings per effect (in each entry) and must meet their totals.
- **--compare:** `--shot <name> --compare` renders the same frame once per look and writes one PNG with Vanilla on the left and Trailer on the right, labeled. This is how M55–M58 take their one screenshot.
- **Tests:** the vanilla reference comparison for all six scenes; the options round-trip (look, quality, per-effect overrides, both pack lists) and the migration from an M53 options file; F12 switches the look and the overlay message shows; the pack matcher; the vertex attribute packs and unpacks every normal direction and material class; a startup timing test logged in the PR.
- **Done when:** the tests pass, the perf gate shows Vanilla within 3% of M53 and Trailer (still plain) close to it, and the PR has the pass list and the profiler's output. No screenshot.

### - [x] M55 — Sunlight, shadows and light through the leaves
- **Step 0:** print, for the forest-noon and cave-torches scenes: the sun's direction from the celestial angle (vanilla's sun path is east to west over the zenith, tilted 0°), the sky-light and block-light levels at five sample pixels, and what the Trailer pipeline draws there now. Count triangles drawn per frame for the main view and estimate the shadow pass's count. Check which leaves Better Leaves changes and that they load with alpha holes.
- **Sun and moon light:** one directional light that follows the sun from sunrise to sunset and the moon at night, faded through a short crossfade at dawn and dusk so shadows never pop. Daylight is warm white, low sun is orange, moonlight is dim and blue. Rain and thunder dim it (vanilla's rain level). Direct light = sun color × max(0, N·L) × shadow, and it is multiplied by a sky-light factor (a smooth step over sky light 0–15 at the face), so places with no sky light (caves, closed rooms) never get sunlight even where the shadow map can't see. Ambient light is vanilla's sky-light curve tinted by the sky color, plus vanilla's block light curve for torches, a little warmer than vanilla's. Faces keep vanilla's per-vertex ambient occlusion, made softer and slightly stronger in corners. Mod brightness overrides (Fullbright) and the Brightness option still work: with Fullbright on nothing is darker than in Vanilla.
- **Shadow maps:** cascaded shadow maps from chunk meshes (opaque and cutout only), drawn from the light's direction, with cascades snapped to whole shadow texels so they don't shimmer when the camera moves. Low: 1 cascade, 1024², 40 blocks, 4-tap PCF. Medium: 2 cascades, 2048², 24 and 96 blocks, the far one refreshed every other frame, 8-tap soft PCF. High: 3 cascades, 2048², 16, 64 and 160 blocks, 16-tap soft edges that widen with distance from the caster. Cull chunks against each cascade's box, skip chunks fully underground (no sky light in the column's top section and none exposed), and cache: when the light has moved less than 0.05° and no chunk in the cascade changed, reuse the far cascades. Shadows fade out at the end of the last cascade. Use slope-scaled depth bias and a small normal offset so there's no shadow acne or light leaking at block edges.
- **Pixel-locked shadows (on by default, like Reimagined):** shadow lookups snap the sample position to the 1/16-block texel grid of the face, so shadow edges are crisp pixel steps that match Bare Bones' flat textures. Toggle in Trailer Settings.
- **Light through the leaves:** the shadow pass alpha-tests leaves and plants with their textures, so sunlight falls through Better Leaves' holes as dappled spots. Leaves and grass also get a soft see-through light when the sun is behind them (subsurface, cheap: a wrapped N·L term). With Fast graphics (solid leaves) the leaves cast solid shadows.
- **Entities:** mobs, players, item drops and the hand are lit by the same sun and read the shadow maps. Medium and High: mobs and players also cast shadows (not item drops); Low: they don't. Vanilla's round entity shadow blob is hidden in Trailer when real shadows are on.
- **Tone mapping and color:** HDR shading, then a filmic tone curve tuned so that a fully sky-lit grass block at noon in Trailer is within 10% of Vanilla's brightness, with slightly richer saturation (about +10%) and a soft warm tint at sunrise and sunset. No vignette.
- **Dimensions:** no sun or shadows in the Nether and the End. The Nether gets warm ambient light and its own fog (M57), the End a faint purple ambient. Their block light and tone mapping follow the rules above.
- **Tests:** the sun direction at ticks 0, 6000, 12000 and 18000 matches vanilla's angles; the cascade split and texel snap are stable (moving the camera half a texel doesn't change the cascade's projection); a closed 5×5×5 stone room at noon with a torch gets no sun term anywhere inside; with Fullbright on, no pixel in cave-torches is darker in Trailer than in Vanilla; the tone curve keeps sky-lit noon grass within 10% of Vanilla; Fast graphics leaves cast solid shadows.
- **Done when:** the tests pass, the perf gate passes with the shadow and shading times within their shares, and one screenshot: forest-noon at 9 am in game time, --compare, with dappled light under the trees and shadows on the grass.

### - [ ] M56 — Water and sky
- **Step 0:** print how water's surface is meshed now (top faces only? the M51 culling), its texture and tint per biome (M47), and what's drawn under it. Time the sky and cloud passes.
- **Water surface:** the vertex shader moves the top faces of still water up and down by at most 0.05 blocks (not flowing water's slopes, not the sides), and the fragment shader adds small moving waves to the normal (two scrolling procedural noise layers, no new textures). Bare Bones' water texture and M47's biome tints stay underneath.
- **Reflections:** a Fresnel term (Schlick, water's F0 0.02) mixes in a reflection. All profiles reflect the sky (the same sky shader sampled in the reflected direction, with clouds on Medium and High). Medium: screen-space reflections at half resolution with 16 steps and a binary refine, falling back to the sky where the ray leaves the screen or hits nothing, and only on water and ice. High: full resolution, 32 steps, also on glass and the metal blocks. No reflections of things that are off screen. Reflections fade with the sky light at the surface, so water in caves doesn't reflect a bright sky.
- **Refraction and depth:** Medium and High copy the opaque scene's color and depth before translucent faces, and water shows what's under it shifted slightly by the wave normal, tinted by the biome's water color more strongly the deeper the water is (absorption over the distance through water), so shallow water is clear and deep water is dark blue. Low: vanilla's blending with the wave normal and sky reflection only.
- **Sun glints:** a sharp sun highlight on water (and a faint one on ice), fading out in rain.
- **Under water (keep M51's fog distances and colors exactly):** on High, moving caustic light patterns on lit surfaces under water (procedural, in the world shader, masked by sun shadows) and the surface seen from below shows the sky through a Snell's window with total reflection outside it.
- **Sky:** keep vanilla's sky color, sunrise color, stars and moon phases from the existing sky shader, and add a soft glow around the sun and moon, a brighter horizon haze that matches the height fog (M57), and a slightly deeper blue overhead. Sun and moon keep their textures from the pack (square, like vanilla).
- **Clouds (Reimagined style, still blocky):** keep vanilla's cloud layout, height and speed (the existing cloud shader's grid) and the Fast/Fancy/Off option, and shade the boxes: lit tops, darker bottoms, a warm edge at sunset, and fading into the distance. Medium and High: clouds cast soft moving shadows on the ground (the cloud grid sampled along the sun direction in the world shader, no extra pass).
- **Tests:** the Fresnel term is 0.02 straight down and above 0.9 at grazing angles; the wave displacement never exceeds 0.05 and is 0 on flowing water; at 0 blocks deep water's tint is 0 and grows with depth; the M51 fog numbers are unchanged in Trailer (a test with t = 0, 100 and 600 ticks); in a cave lake with sky light 0, the reflection has no sky in it; the vanilla reference test still passes.
- **Done when:** the tests pass, the perf gate passes with water within its 0.8 ms and sky/clouds within 0.3 ms, and one screenshot: lake-sunset, --compare, showing the sun's glint, reflections of the shore and the sky, and shaded clouds.

### - [ ] M57 — Light shafts, bloom, swaying plants, rain and finish
- **Step 0:** print the post chain as M56 left it with each pass's time, and how particles, rain and splashes are drawn now (src/render and the particle system).
- **Light shafts (volumetric light):** a ray march through the shadow map from the camera, so sunlight shows as shafts through leaves, cave openings and windows, scaled by sun height (strongest at sunrise and sunset), weather (stronger in rain mist) and a height falloff. Low: off. Medium: quarter resolution, 8 steps with blue-noise jitter, a depth-aware 4×4 blur and upscale. High: half resolution, 16 steps. Under water (Medium and High), shafts come from the surface (M51's fog color, using the same shadow map). No shafts in the Nether or the End.
- **Bloom:** bright HDR pixels (the sun, emissive blocks from materials.ron, lava, fire, water glints) glow softly: a downsample/upsample chain of 5 mips at Medium and High, 4 at Low, with a threshold so ordinary daylight scenes don't get hazy. Emissive blocks are drawn above 1.0 in HDR so they bloom; their light on surroundings still comes from vanilla block light.
- **Swaying plants:** in the vertex shader (and the same motion in the shadow pass), leaves move slightly, grass, flowers, ferns, crops and saplings bend at the top (the bottom vertices stay put), vines and hanging roots sway, all by world position and game time, stronger in rain and thunder. At most 1/16 block for leaves and 3/16 for plants, so plants never clip through the block above. All profiles.
- **Rain:** while it rains, sky-lit surfaces get darker and slightly glossy (wet), and rain makes rings on water surfaces (Medium and High). The wetness fades in and out over about 10 seconds after rain starts or stops. Snow biomes don't get wet.
- **Splashes and waterfalls (in the style of the Effective mod):** particles where falling water lands in still water (white foam and a little mist, at most 32 particles per waterfall, only within 32 blocks), and a splash when a mob or player falls into water fast. Use the existing particle system and textures from the packs (vanilla's splash and bubble textures). Trailer only, with a "Splashes" toggle in Trailer Settings; Vanilla never gets them.
- **Height fog and dimension fog:** Trailer adds a thin height fog over the vanilla fog (thicker in the morning and over water, never shortening vanilla's render-distance fog or M51's underwater fog). The Nether gets a thick warm fog tinted by each biome's fog color, the End a dark purple one. The sky's horizon haze (M56) uses the same color.
- **Anti-aliasing:** FXAA at Medium and High as the last pass before the UI, tuned so pixel-art textures stay sharp (edges only, no blur inside faces). No TAA.
- **Profiles:** check every Trailer setting has a Low/Medium/High value from the entries, the Trailer Settings screen shows them all, and turning any single effect off removes its pass (its GPU time goes to 0 in the profiler).
- **Tests:** the plant sway never moves a bottom vertex and stays within 3/16 of a block; the bloom threshold leaves a plain noon grass field unchanged within 2%; shaft strength is 0 when the sun is below the horizon and in the Nether; turning off each effect removes its pass from the profiler's list; the vanilla reference test still passes.
- **Done when:** the tests pass, the perf gate passes for all four rows with every effect inside its share, and one screenshot: a forest at sunrise on seed 12345, --compare, with light shafts through the trees.

### - [ ] M58 — Fresh Animations: custom entity models and animations
- **What Fresh Animations needs:** it's an OptiFine CEM resource pack (models and animations for most vanilla mobs in assets/minecraft/optifine/cem/*.jem and *.jpm, plus textures), which modern players run with the Entity Model Features (EMF) and Entity Texture Features (ETF) mods. M58 makes Rustcraft read that format, enough for Fresh Animations on every mob Rustcraft has.
- **Step 0:** list the .jem, .jpm and .properties files in the Fresh Animations pack in resourcepacks/, and, for every Rustcraft mob in mobs.ron, whether Fresh Animations has a model for it. Count the animation variables and functions its files use (grep them all and print the list with counts), and which ETF features it uses (emissive _e textures, random or per-variant textures, blinking eyes). Time how long building the mob meshes takes per frame now with 100 mobs on screen.
- **Vanilla part names:** give every part in mobs.ron the name vanilla's model uses for it (head, body, right_arm, left_leg, …; OptiFine's CEM part list for each entity is the reference), and check each mob's default model against vanilla's sizes and pivots. Mobs keep their current look and animations when no pack has a model for them.
- **The CEM loader:** read .jem files (texture, textureSize, shadowSize, models with part, id, attach, invertAxis, translate, rotate, mirrorTexture, boxes with textureOffset or per-face uv, coordinates and sizeAdd, submodels, and .jpm model files referenced by "model") from the resource pack layers, top pack first, from optifine/cem/ and the paths EMF also reads. A part in the .jem replaces the vanilla part with the same name (or attaches to it with "attach": true). Unknown fields are ignored with one log line per file, never a crash. Support the variant suffixes Fresh Animations uses (e.g. a different model per variant or baby) the way EMF does.
- **The animation engine:** CEM animations are lists of `target = expression` lines (part.tx/ty/tz, rx/ry/rz, sx/sy/sz, visible, var.name, varb.name, render.*), evaluated every frame in order. Parse every expression once at load into a compact bytecode (constants folded), never re-parse per frame. Support the operators, the math functions (sin, cos, asin, acos, tan, atan, atan2, torad, todeg, min, max, clamp, abs, floor, ceil, exp, frac, log, pow, random, round, signum, sqrt, fmod, if, ifb, lerp, between, equals, in, print, printb, and any others Step 0 found), and the entity variables Fresh Animations reads (limb_swing, limb_speed, head_yaw, head_pitch, age, frame_time, time, day_time, health, max_health, hurt_time, death_time, swing_progress, pos_x/y/z, rot_x/y, move_forward, move_strafing, is_on_ground, is_in_water, is_in_lava, is_riding, is_ridden, is_burning, is_hurt, is_aggressive, is_child, is_sneaking, is_sprinting, is_wet, is_alive, id, player_pos_x/y/z, and EMF's additions Step 0 found). Variables Rustcraft can't know yet return vanilla's default (0 or false) and are listed once in the log. Per-entity var values are kept between frames for each mob. Interpolate with the frame's partial tick like the rest of the renderer.
- **ETF essentials:** emissive textures (texture_e.png drawn full bright over the mob, and blooming in Trailer), random and per-variant textures from optifine/random/entity/ .properties (by biome, name, health, height, baby and the other rules Fresh Animations uses), and the blinking-eyes textures if it uses them.
- **Sync:** animations are drawn on each client from synced mob state; add any state the variables need that clients don't get yet (aggressive, sneaking-like poses, riding) to the mob sync from M36. Both clients in the two-client test must compute the same var values for the same mob on the same tick.
- **Performance:** with 100 animated mobs on screen, building their meshes and running their animations takes at most 1.0 ms per frame on the M1 (measure it), using a cached part tree per model and reused buffers. The Trailer budgets still hold.
- **Both looks:** CEM models come from resource packs, so they show in whichever look has Fresh Animations in its pack list (the Trailer list by default). Vanilla's default list is empty, so Vanilla still matches the reference images.
- **Tests:** the expression parser and bytecode against a table of expressions with known results (including operator precedence, if/ifb, nested functions and var persistence); a .jem fixture written for the tests (not Fresh Animations' files) loads with the right part tree, pivots and uvs; a part replaced by CEM keeps its vanilla name for attachment; every Fresh Animations file in resourcepacks/ loads with no errors (a test that's skipped with a message when the pack isn't there); with the pack loaded, every mob with a .jem has an animated model and every other mob looks the same as before; the 100-mob timing; two clients agree on a villager's and a zombie's var values over 200 ticks.
- **Done when:** the tests pass, the PR lists which Rustcraft mobs Fresh Animations now animates and which variables are still unsupported, the perf gate passes, and one screenshot: a village on seed 12345 at noon with villagers, a cow and a chicken in view, --compare (Vanilla without Fresh Animations on the left, Trailer with it on the right). **Stop: Checkpoint K.**

# M75 native perf gate (against v1.5.0, same session)

M75 (`011e42b`) and v1.5.0 (`2a88c35`) each built in a clean worktree and measured back to back on the M1 Mac mini (the machine `docs/perf/baseline.json` is from; the display is 60 Hz, so the fixed baseline's 120 Hz-era numbers aren't comparable, as in M70–M73). `--perf-test --runs 3`, then `cargo bench` for each.

| Measure | v1.5.0 | M75 |
|---|---|---|
| average_fps | 82.28 (spread 1.6%) | 82.07 (2.0%) |
| one_percent_low_fps | 46.66 | 47.03 |
| worst_frame_ms | 32.05 | 37.24 (spreads 44% / 69%) |
| chunk_generation_ms | 8.04 | 8.11 |
| light_mesh_ms | 8.17 | 8.17 |
| memory_mib | 715.7 | 711.4 |

| Bench | v1.5.0 | M75 |
|---|---|---|
| generate a chunk | 2.689 ms | +1.3% |
| generate a nether chunk | 1.396 ms | +0.1% |
| generate an end chunk | 34.7 µs | -6.6% |
| light a chunk | 1.171 ms | +5.6% |
| mesh a chunk | 2.078 ms | -9.0% |

Result: **not clearly worse than v1.5.0 beyond its run-to-run spread** (frame rate within 0.3%; the light +5.6% / mesh -9.0% pair is the same noise seen in M71, M72 and M73, and nothing here touches lighting or meshing). M75's native changes are small: a `music:` log line, the in-memory storage's modification clock (browser only), `options::default_visuals` (browser only) and the boot-time vanilla check (browser only). Golden hashes unchanged; `tests/vanilla_reference` passes.
